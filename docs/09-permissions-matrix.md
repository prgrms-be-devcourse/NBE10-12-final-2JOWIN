> 요구사항 v1.6 SC절 × ERD v1.6(25테이블)을 곱한 결과다. **이 표가 API 명세서의 "역할" 칸과 서비스 레이어 권한 검사의 기준이다.** **표에 없는 조합은 전부 불가**가 기본값.
> 변경은 팀 합의 + 버전 업으로만.

## 전역 규칙 (모든 행에 적용)

| 규칙 | 내용 | 근거 |
| --- | --- | --- |
| 테넌트 격리 | 모든 `/api` 요청은 토큰의 company_id로 스코프. 타사 리소스는 역할 무관 접근 불가 | SC-01 |
| 무권한 = 미존재 | 권한 없는 **리소스** 접근은 403이 아니라 **404** — 존재 여부를 숨김 (역할 자체로 갈리는 행위는 예외 — 아래 구현 위치) | SC-09 |
| 담당 변경 시 | 이전 담당자는 그 즉시 해당 Deal·견적·주문 접근 상실 (이력의 작성자 표기는 유지) | SC-06, AC-08 |
| 회사 정지 시 | 구성원 전원 즉시 차단 — 역할 무관 (refresh 전 행 폐기) | ON-09 |
| 회사 정지 시 (고객 링크) | 열람은 유지, 승인·반려는 차단 → `COMPANY_SUSPENDED` | SC-10, Q-27 |
| 구성원 비활성화 | 담당 Deal 이관 대상 지정 필수(할 일은 자동 이동) — 미지정 시 `MEMBER_INACTIVE_TRANSFER_REQUIRED` · 효과: 세션 전체 폐기 | MB-14, Q-29 |
| 인증 토큰 | refresh·재설정 토큰은 **본인 것만** — 타인 세션 조회·폐기 API 없음 (관리자의 강제 차단은 비활성화·정지의 효과로만) | v1.5 |
| 비활성 구성원 | 로그인 불가 — 권한 이전에 인증에서 차단 | MB-10 |
| 🔶의 정의 | Deal·견적·주문·상담·할 일은 Deal의 `assignee_member_id` 기준 — 고객사는 회사 공유(담당 개념 없음) | ERD v1.6, SC-02~04 |

## 구현 위치 (참고)

| 층 | 담당하는 검사 | 응답 |
| --- | --- | --- |
| 인증 필터 | 로그인 여부 · 회사 정지 · 구성원 비활성 | 401 |
| 역할 검사 (@권한 어노테이션) | 표의 ⭕/✕ — **역할 자체로 갈리는 행위** (예: 영업 담당자의 카탈로그 편집, 담당자 변경, 감사 로그 조회) — 리소스 존재를 노출하지 않으므로 SC-09와 충돌 없음 | 403 **`FORBIDDEN`** — "이 작업을 수행할 권한이 없습니다." (Q-43) |
| 서비스 레이어 | 🔶 담당 스코프 · ▫ 본인 작성 여부 — 리소스 단위 판정 | **404** (SC-09) |

> ✅ 403 응답의 ErrorCode·문구는 **Q-43으로 확정**(`FORBIDDEN` / "이 작업을 수행할 권한이 없습니다.") — API 명세서 부록과 신설 코드 요약에 수록됨. ErrorCode enum PR에 그대로 반영한다.
