## 0. 공통

### 0.1 브랜치

| 브랜치 | 용도 | 직접 push |
| --- | --- | --- |
| `main` | 최종 제출본 | 금지 |
| `release/{버전}` | 차수 완료본 — 1·2·3차 → `release/1.0.0` / `1.1.0` / `1.2.0` (현재 기획 1차 = 1.0.0) | 금지 |
| `develop` | 통합 브랜치 | 금지 (PR만) |
| `{타입}/{도메인코드}_{이슈번호}` | 도메인별 개발 (작업 브랜치) | 허용 |

### 0.2 네이밍

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 작업 브랜치 | `{타입}/{도메인코드}_{이슈번호}` | `feat/AU_26` · `fix/QT_41` |
| 커밋 | `{타입}: 요약` (콜론 앞 공백 없음) | `feat: refresh 토큰 회전 구현` |
| PR 제목 | `[도메인] 요약 (#이슈번호)` | `[A] 로그아웃 멱등 처리 (#24)` |
| Flyway | `V{도메인번호대}__요약.sql` | `V101__add_refresh_token_index.sql` |

- 타입(브랜치·커밋 공용): `feat` · `fix` · `refactor` · `docs` · `test` · `chore`
- 브랜치명에 `#`을 넣지 않는다 (`feat/AU_26` ⭕ / `feat/AU_#26` ✕ — 셸에서 주석으로 해석되어 사고 유발).
- Flyway 번호대: **A=1xx · B=2xx · C=3xx · D=4xx** (병렬 작업 시 버전 충돌 방지). `V1__baseline.sql`(25테이블)은 E가 작성 — 업무 분담 §1.2. 이후 각 도메인의 스키마 변경만 자기 번호대에 추가한다.

## 1. 브랜치 흐름

```
feat/AU_{이슈번호} ─┐
feat/CU_{이슈번호} ─┼─ PR ─→ develop ── 차수 완료 ─→ release/1.0.0 ── 제출 ─→ main
feat/QT_{이슈번호} ─┤            ↑                        │
feat/NT_{이슈번호} ─┘            └──────── 백머지 ────────┘
```

| 규칙 | 내용 |
| --- | --- |
| release 버그 수정 | release 브랜치에서 수정 → **develop으로 백머지 필수**. hotfix 브랜치 없음 |
| 차수 완료 판정 | 해당 차수 칸반 이슈 전부 Done + CI 통과 |
| main 머지 | release → main 단방향. main에서 develop으로 되돌리지 않음 |

## 2. PR 파이프라인

```
push → PR 생성 → CI → 팀원 승인 1인 → Squash merge
```

| 단계 | 차단 여부 | 비고 |
| --- | --- | --- |
| CI (빌드·테스트·Flyway) | **차단** | required check |
| 팀원 승인 | **차단** | 1인 이상. CODEOWNERS 자동 배정 · 리뷰 관점은 §2의 셀프 체크리스트와 동일 |

### 브랜치 보호 규칙 (`main` · `release/*` · `develop`)

- 직접 push 금지 · force push 금지 · 브랜치 삭제 금지
- required check = CI 잡만
- 승인 1인 이상

## 3. CI

| 잡 | 내용 | 실패 시 |
| --- | --- | --- |
| build | 컴파일 + 단위 테스트 | 머지 차단 |
| flyway-validate | 적용된 마이그레이션 파일 변경(체크섬) 검사 | 머지 차단 |

- 트리거: `pull_request` (develop · release/* · main 대상)

- 목표 실행 시간 5분 이내

## 5. 칸반 연동

```
이슈 생성(Todo) → 이슈 번호로 브랜치 생성(In Progress) → PR 생성(In Review) → 본문 Closes #N → 머지 시 자동 Done
```

| 컬럼 | 진입 조건 |
| --- | --- |
| Todo | 이슈 등록 |
| In Progress | 작업 브랜치 생성 |
| In Review | PR 생성 |
| Done | develop 머지 (`Closes #N` 자동) |

이슈 라벨: `A` · `B` · `C` · `D` · `E`(인프라) — 담당 + `1차` · `2차` · `3차` — 차수

> 차수 ↔ 일정 매핑: **1차 = 업무 분담 §8의 4주 계획 전체(v1 범위)** — 주차 게이트(1주 말·2주 금·3주 금·4주 중)는 1차 안의 중간 점검이다. 2·3차는 다음 버전 범위가 확정된 뒤 정의한다. (검수 보정 2026-08-26)
