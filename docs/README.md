# 2JO · Deal-to-Order SaaS

> 중소 B2B 영업팀을 위한 **견적 발송·승인 추적 도구.**
> 딜을 단계로 관리하고, 견적을 만들어 링크로 보내고, **계정 없는 고객**이 열람·승인한 사실을 기록으로 남기고, 승인된 견적을 주문 스냅샷으로 확정한다.

영업팀은 견적을 보낸 뒤 고객이 어떤 상태인지 알 수 없고, 최종 합의가 메일과 전화 속에 흩어진다. 2JO는 그 **"발송 이후의 깜깜한 구간"**을 기록으로 바꾼다 — 자세한 문제 정의는 [01](01-problem-definition.md)부터.

|  |  |
| --- | --- |
| 팀 | A 조민석 · B 한상민 · C 최선진 · D 이준형 · E 김대연 (5명 · 4주) |
| 스택 | Java 21 · Spring Boot 3 · PostgreSQL · React · TypeScript · Radix Themes |
| 기준일 | 2026-08-27 |

## 문서 간 기준 관계 — 충돌하면 누가 이기는가

```
01 문제 정의 ─ 02 가정·리스크
      │  (왜 → 무엇)
03 요구사항 (ON-xx · Q-xx)          ← 모든 명세의 근거
      │
05 상태 전이표 (영문 코드 = DB enum = API 값)
      │
 ┌────┴────┐
06 ERD    07 API ── 08 DTO
 │           │
 │        09 권한 매트릭스
 └────┬────┘
   10 화면 설계 ─ 11 업무 분담 ─ 12 프론트 ─ 13 워크플로우 ─ 14 스택
```

- 상태·단계의 **영문 코드는 05가 원본** — ERD CHECK, API 응답 값, DTO enum이 전부 따른다.
- ERD는 **"주요 테이블 상세" 표가 원본**, Mermaid는 그것을 따른다.
- 필드 상세는 **08**, 에러 코드·문구는 **07 부록**, 역할·스코프 판정은 **09**가 원본이다.
- 화면의 시각 정본은 **와이어프레임 v2 캔버스**(10 §10), 공통 개발 컨벤션의 정본은 **11 §1**이다(Q-36).
- 본문의 "v1.6" 표기는 **v1.6.x 계열**을 가리킨다 — 정확한 버전은 각 문서 변경 이력 참조.
