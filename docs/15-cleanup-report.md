## 2. 발견·해소한 불일치

### 2-1. 중복 문서

`api 명세서 ㅍ1.6`은 `API 명세서 v1.6`과 내용이 동일한 사본이었다(파일명 오타 `ㅍ1.6`). 두 사본이 각자 수정되기 시작하면 어느 쪽이 정본인지 알 수 없게 되므로 하나로 통합했다.

### 2-2. 업무 분담 v1.0의 구버전 잔재 (전면 갱신 사유)

v1.0(8/21)은 v1.6 확정 전의 설계를 기준으로 작성되어, 그대로 따르면 구현이 v1.6 문서 세트와 충돌한다.

| 항목 | v1.0 (구) | v1.6 확정 (신) |
| --- | --- | --- |
| 테이블명 | tenant · app_user · signup_request · quotation · quotation_item · quote_share · secure_token · outbox_event | company · member · application · quote · quote_item · quote_view_token · refresh_token/password_reset_token · email_log |
| Deal 단계 | LEAD/**QUALIFIED**/**PROPOSAL**/NEGOTIATION/WON/LOST | LEAD/**CONSULT**/**QUOTE**/NEGOTIATION/WON/LOST (전이표 §5) |
| 고객사 담당 | `customer.owner_id` 신설이 "블로커" | **담당 개념 자체를 제거** (SC-03 재정의, created_by_member_id는 기록용) |
| 경로 체계 | /api/... · /api/platform · /api/t/{token} | /api/v1 · /admin/api/v1 · /public/api/v1 |
| 금액 타입 | NUMERIC(19,2) | **BIGINT 원 단위 정수** (Q-12) |
| 부가세 | vat_type EXCLUSIVE/INCLUSIVE | vat_mode **EXCLUDED/INCLUDED** (기본 EXCLUDED, Q-16) |
| 견적 상태 | REJECTED까지 (6+1상태 나열 순서 상이) | 7상태 확정 + 만료 사유 5종 |
| 초대 상태 | REVOKED | **CANCELED** (전이표 §3) |
| 역할 | COMPANY_ADMIN / **SALES** | COMPANY_ADMIN / **SALES_REP** (ERD member.role) |
| 에러 포맷 | {code, message, traceId} · 권한 없음 403 | ErrorResponse{code, message, **fieldErrors**} · 범위 밖은 **404** (SC-09) |
| 범위 제외 목록 | AC-09(할 일)·AP-15(문의)·NT-05/06(배치)·DB-06~08 "제외 권장" | **전부 v1 범위에 포함** (task·customer_inquiry 테이블, NT 배치, dashboard/performance 존재) |

| 참조 문서 | "06 보안 대응 설계 v2.0" 기준 | 해당 문서 부재 — v2.0에서는 참조 제거, 실체 있는 v1.6 문서만 참조 |

유지한 것: 담당 구조(A~E), "테이블 하나에 소유자 한 명" 원칙, 인터페이스 경유 규칙, 이벤트 기반 자동 기록, 주차별 계획과 게이트, 동시성 테스트 선작성, 마이그레이션 번호 대역. — v1.6 API 명세서의 담당 표기·경계 합의와 일치하는 부분은 그대로 살렸다.

### 2-4. 권한 매트릭스 v1.6 (추가 확보분)의 불일치 (수정 완료)

정리 1차 때 부재했던 문서로, 이후 확보되어 API 명세서 v1.6과 전수 대조 후 편입했다. 매트릭스의 역할·범위 판정은 API 명세서·SC절과 거의 완전히 일치했고, 다음 4건만 손봤다.

| # | 위치 | 문제 | 조치 |
| --- | --- | --- | --- |
| 1 | 본인 계정 행 | 플랫폼 관리자 ⭕ (프로필·비밀번호·알림 설정) — 그러나 **API 명세서에 해당 /admin 엔드포인트가 없다** ("표에 없는 엔드포인트는 v1에 없다"). AU-11(관리자 비밀번호 화면 재설정)도 미룸 상태 | ⭕ → ▫로 조정, 비고에 "v1 엔드포인트 없음 — 세션 관리만 존재, 재설정은 운영 런북" 명시 |

| 3 | 🔶 정의 근거 | "ERD v1.2" 참조 | ERD v1.6으로 현행화 |
